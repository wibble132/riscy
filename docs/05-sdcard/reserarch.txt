SD Card:

Knowing how the spi on the chip works, what does sd card want in spi mode?

- I send a command
- THEN I get a response

So I need to write command, clear FIFO, then write nonsense data (of the desired response length), read FIFO.

See SD card Physical Layer Section 7.3 SPI Mode Transaction Packets

e.g.

Sending CMD0:

- start bit, transmission bit:		01
- command index:			000000
- argument:				00000000_00000000_00000000_00000000
- CRC7:					???????
- end bit:				1

And this should be sent as bytes. One at a time. So we send 0b0100_0000,0,0,0,0,0b0000_0001 (0x40,0x00,0x00,0x00,0x00,0x95)

CRC:

The CRC7 uses generator polynomial x^7 + x^3 + 1

so the crc7 of 01 000000 00000000_00000000_00000000_00000000
                                           _______
is 00000000000000000000000000000000000000001001010
                                          76543210

What is a computer algo for this?

 1. Split into bytes. Have array<u8, 5>.
 2. Take 2 bytes, $val
 3. for $s in 15..=7 { if bit (1<<$s) is set in $val, `xori $val,$val,(0b10001001 << ($s-8)) }
    assert!($val is now 1 byte, <128)
 4. if more bytes:
      $val = ($val << 8) + (next byte in array)
      jump to 3.
 5. CRC7 is left in $val (should be <128)

SD Card SPI Responses:

Many commands just send an R1 result - all 0 means all good!
(I think all the commands I use just send R1)

Read commands send the R1 response, then the data (if no error). Data is followed up with a CRC. After that, it is ready to have another command.
  If error in read, sends a "data error" token -

Writing data:
  - send write command
  - receive response R1
  - send "start block" token (1byte)
  - poll the response, will get "data response" then a busy signal until it is ready again
  - send a SEND_STATUS command to check for other errors
  - "busy" state just holds the data line low, so will read as constant stream of (0s or 1s)


Note on SD card SPI:
  - host starts transaction by pulling CS low (This means the rp2350 has SPO=1, SPH=0)
  - always get a response

  spo = 0b1
  sph = 0b0

  dss = 0b0111 // 8-bit data (TODO - double-check against the sd-card format

  write_byte(SSPCR1, 0b0000_0010);
}
